## Question 3
### Question b
#### (i)
Static data segment and dynamic data segment. In static data segment, global variables and local variables are stored here. The variables exist throughout the whole program with its values maintained. The variables are allocated in the beginning of the program and is deallocated when the program terminates. The variables can be accessed anywhere from the program. In dynamic data segment, objects are created only when the program requests for it.  The objects are deallocated when it is no longer used to prevent memory leaks. It can be accessed from anywhere in the program as long as there is a valid reference to them.
#### (ii)
Function call management. When a function is called, the information on the local variables and return address are pushed onto the stack. This allows for a more orderly execution of the function and allows the return back to the function caller. 
Store local variables. When a function is called, space for the local variables are allocated in the stack segment. When the function is finished executing, the space is deallocated. 
### Question b
#### (i)
Data bus width determine the amount of data that can be transferred at a time. A wider data bus width means more data can be transferred at a time. A wider data bus width increases the data transfer rate between the CPU, memory and the peripherals.
#### (ii)
Address bus width determine the maximum amount of memory the computer can address. A wider address bus width means the computer have a larger amount of memory space, accommodating large RAM and memory-mapped I/O. This allows the computer to handle more complex programs
### Question c
**Programmed I/O**
1. The CPU does the data transfer in this mode. 
2. The CPU engages in polling where it has to constantly wait for response from the peripherals. 
3. It is slow
4. The CPU has to constantly send request and check so as to not miss anything important but this causes the CPU to not be able to do anything else. 
**Interrupt-driven I/O**
1. The CPU has the freedom to do its own thing while waiting for the device to be ready.
1. The CPU completes the current instructions
2. Saves the instruction address of the next instruction in address register
3. Completes the instructions from the interrupt
4. Jump to the address register
**Direct Memory Access**
1. A special hardware is needed. 
2. The CPU does not do data transfer
3. The CPU request DMA to do data transfer between the peripherals to memory.
4. DMA request control over the I/O device and waits. DMA does the data transfer between the peripherals and the memory directly. 
5. DMA issues an interrupt signal when the data transfer has been completed. 
DREQ -> HOLD -> HLDA -> DACK 
**DREQ** -> the I/O device request data transfer
**HOLD** -> The DMA requests the CPU to release the system bus
**HLDA** -> The CPU acknowledges the request and releases the system bus
**DACK** -> The DMA acknowledges the request and initiates data transfer

### Question b
No. In single cycle, each instruction is complete in a single cycle. The clock cycle is set to accommodate the slowest instruction, that is lw. The instructions that take lesser time to complete still has to wait until the entire clock cycle to finish. However, each instructions in multi-cycle is broken down into stages. Each stage may take one or more clock cycle. Because of this, different instructions have different clock cycles. Single cycle also has poorer resource utilisation. The resources cannot be shared and are allocated for all possible operations even if the instruction does not need it. Multicycle has better resource utilisation. The resources are only allocated when needed for current instruction stage. The resources in multicycle can be shared.  
## Question 5
### Question a
![[Translating HLL to LLL]]
**Compiler**
The compiler will convert each higher level language files into assembly files that contains assembly language
**Assembler**
The assembler will convert the asm files into object files containing machine code. The assembler will:
1. Read and use the assembler directives
	- .text
	- .data
	- .global sym
2. Replaces pseudoinstructions 
3. Assign instruction addresses
4. Creates symbol tables that record addresses of symbols along with their addresses
5. Creates allocation table for items that need addresses later
**Linker**
Merges independent object files to produce a single executable file.
1. Merge text segments and data segments
2. Search for references in the symbol table
3. If it is not in the symbol table, look for them in the library file
4. Determine the absolute memory address
5. Fill the absolute address in machine code
**Loader**
Loads the executable file. The operating system will:
1. Read the executable file header to determine the text size and the data size
2. Create address space in memory for the program
3. Copy and place the instructions and data from the program into the address space
4. Copy the arguments passed into the program onto the stack
5. Initialise the machine register
	- Clears up the registers
	- Set $gp, in the middle of the stack pointer
	- Set $sp, on top of the stack pointer
6. Jump to the beginning of the program.
