### Question A
#### Question I
Employee: VARCHAR2

#### Question II
Existence-dependent
- Order
	- Order entity is an associative entity. It exists to resolve the many to many relationship between sales and product
	- The order entity itself cannot exist without the association of other two entities that is, sales and product
		- The order entity can only exists when it is associated with occurrences from sales and product entities
	- It's primary key is derived from other entities
Existence-independent
- Employee
	- Employee entity can exist on its own apart from one or more entities
	- as its primary key is not derived from any other entity.
#### Question III
Sales entity. It exists to resolve the many to many relationship between employee and customer entity. 
#### Question IV
Referential integrity. Its foreign key values must match existing values in its parent relations, employee relation and customer relation. Referential integrity constraint that can be placed is cascade update. Whenever the values in the parent tables are updated, the values in the sales entity should be updated as well to prevent data inconsistency. Another constraint that can be placed is cascade delete. Whenever the values from parent entity employee or customer is deleted, the associated tuple in entity can be deleted to preserve data integrity. However, this implementation depends on how the organisation views the sales data
### Question B
Data redundancy refers to the repetition of similar tuples in a relation multiple times in different places. 
Data inconsistency refers to the lack of uniformization or standardisation of data in different places. For instance, data inconsistency happens when two databases which is supposed to handle the same data, receives different input. For example, the salary of a person is different in one database than another.
### Question C

	1. Prohibit the parent occurrence to be deleted

	1. Delete the child occurrence along with the parent
3. Set NULL
	1. Set the attribute that is related to the parent occurrence to NULL
4. set Default
	1. Provide default value to the attribute that is related to the parent occurrence
