### Question D

1. Complexity in development
	- Developers have to consider edge cases and other potential application-breaking bugs before deploying the features
2. Users may experience choice paralysis
	- Interactivity introduces choices to the user, especially if the user are given multiple choices of what kind of content that they will see. Too many choices may overwhelm the user
3. Increases the hardware requirements for smooth experience compared to non-interactive multimedia applications.
    - The application has to process user input and provide feedback in real-time. 
    - This requires a hardware that can listen and process to signals constantly, unlike non-interactive applications that only require hardware sufficient enough for processing.
4. Interactive multimedia contents increases the risk of malware
    - This is because these applications require user inputs, script execution, and dynamic data processing that malicious users can exploit. For example, the JavaScript of a website can be injected with malicious script without the knowledge of the user.
5. Interactivity multimedia content introduces accessibility incompatibility.
    - Some multimedia contents can only be interacted with in a specific way. For example, the drag-and-drop feature only works with a mouse. Users who have motor disability or if they are using a screen reader may not be able participate in this interactive activity.

### Question A

#### Question I

1. The number of non-overlapping skills needed to complete the project
    - A multimedia project often requires skills from various fields.
    - For instance, during a game development, there will be separate groups of programmers, each working on their respective components of the game such as designing, modelling or coding.
2. The size and complexity of each feature in the project
    - A complex feature is usually broken down into sub components that are handle separately by a separate groups of developers. 
    - This can help reduce errors and workload compared to having a small group to develop the features entirely.
3. The budget of the development project
    - A higher development budget allows for more team members to be hired, while a lower budget requires the project manager to be more thorough in hiring individuals.
    - Often time, a smaller budget forces project manager to hire generalists so that the team can cover a wide area of skills; however, this may impact the quality of the final product negatively. 

### Question II

1. Strong communication in the development team.
    - Good communication is necessary to reduce misunderstanding and ensure that any issues that happen can be solved quickly. 
    - This can reduce delays and breaking errors that happen during the development, ensuring goals can be met within the time constraint.
2. Strong coordination in the development team
    - A strong coordination ensures that different developers are not working on the same feature at the same time, preventing conflicts. 
    - It also ensures that the best team member is assigned to work on features that reflect their skills the most.
3. Clearly determined goals
    - Ambiguous goals cause scope creep, whereby the scope of the project grows more and more without consideration of the progress of the project and current workload.
    - Thus, it is important for the development team to clarify the goals and requirements clearly with the clients to ensure the project fulfills the clients' expectations as closely as possible.

MIDI stores digital instructions in numeric format for musical information. It is to instruct how a computer should play musical instruments. It allows an interchange of musical information between musical instruments, synthesisers, and computers. 

#### Question II

The audio data stored in MIDI are the instructions on how to play musical instruments, while the audio data in digital audio contains the amplitude and frequency of the audio. This meant that MIDI can only be played on specific devices that can read MIDI files such as musical instruments and synthesisers, while audio data can be played on most devices. The quality of MIDI is also highly-dependent on the device that it is played on. Because MIDI stores instructions instead of digitised audio waves, the quality of the audio is dependent on the quality of the hardware of the device. For digital audio, the audio remains consistent because the actual waveforms are being reproduced, not synthesised from scratch. Finally, editing a MIDI file is easier than more flexible compared to digital audio, due to the lack of saving waveforms. Users can edit the instructions in the MIDI file. However, for digital audio, editing it is usually distructive or complex as the waveforms are fixed; editing them may cause distortion.

### Question A

1. Design consistency
    - The design of the user interface of one page of an application should remain similar to another. 
    - For example, the navigation icons should remain the same, regardless of the page that the user is on. It is also necessary to keep the positions of various navigational elements similar across various places to ensure.
    - This design consistency is necessary to avoid breaking the immersion of the user by causing them to consciously look for changes.
2. Familiarity
    - User interfaces should use icons and graphics that are common in other applications.
    - This allows the user to know what each icon or button does implicitly without having to look up a guide.
    - Consequently, this keeps the user immerse in the workflow that they are in.
3. Convenience and responsive interaction
    - The user interface should provide feedback to the user immediately after each interaction.
    - For example, the interface should provide an indication of successful interaction, such as a shift in colour of the clicked button to green or playing a sound on completion of specific processes.

### Question C

VR only involves virtual elements and environment while Mixed Reality involves both virtual and physical elements and environment. In VR, the user is completely immersed in a virtual world; the headset completely blocks any real-world elements, while mixed reality intertwine virtual elements with real-world elements

The interactions in VR involve only virtual objects; the user controls a virtual character to interact with a virtual world. Mixed reality allows virtual objects to interact with real-world objects, and vice versa. For example, a virtual ball in mixed reality would bounce when the virtual floor hits the physical floor.

VR requires more extensive processing power, sensors, and trackers, while mixed reality does not; they can be implemented with only a phone. This is because VR involves complete 3D virtual environments that often require extensive modelling, animating, and rendering to provide an immersive experience. Mixed reality only has to render specific 3d virtual models to interact with the real world. The lack of need to render entire expansive virtual environment saves a lot of computing processes and power.
